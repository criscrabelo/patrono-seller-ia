Painel de Metas — pontuação, papéis e rankings

// Pontuação justa = baseada no % da meta (não no valor bruto)
percentual = valorRealizado / valorMeta * 100
pontuacao  = round(percentual)        // 90% → 90 pts; 125% → 125 pts (extras)
falta      = max(0, valorMeta - valorRealizado)

// Status visual por cor
>= 100% azul (concluída) · >= 80% verde · 50–79% amarelo · < 50% vermelho · 0% cinza

// 3 rankings (ordenar por % atingido):
1. Administradores  2. Operadores  3. Times

// Permissões por papel
Admin Geral  → cria admins/operadores/times, todas as metas, vê tudo
Admin Time   → cria/edita metas do SEU time e operadores; vê ranking geral
Operador     → vê suas metas, ranking de operadores, desempenho do time (sem editar)
Tela: app/(dashboard)/metas. O protótipo traz um seletor "Ver como" (Admin Geral / Admin de Time / Operador) só para demonstração — em produção o painel se adapta ao role do usuário logado. Cada admin tem o botão "Ver meu time" (drill-down com operadores, realizado, % e posição).

Painel de Lucro — fórmulas e Score de Escala

// Fórmulas base
comissao      = valorVenda * percentualComissao
lucroLiquido  = comissaoRecebida - custosAtribuidos
margem        = lucroLiquido / comissaoRecebida * 100
conversao     = vendas / cliques * 100
lucroPorVideo = comissaoDoVideo - custoDoVideo

// Score de Escala (0–100): média ponderada normalizada
score = round(
  0.20*nVendas + 0.15*conversao + 0.15*lucroLiquido +
  0.12*comissaoPorVenda + 0.10*nCliques + 0.08*facilidadeVariacao +
  0.08*avaliacaoProduto + 0.06*precoAcessivel + 0.06*baixoCancelamento
) // cada fator normalizado 0–1 antes de ponderar

// Faixas:  0–30 não escalar · 31–60 testar · 61–80 promissor · 81–100 campeão
Telas: app/(dashboard)/lucro (painel) + drill-down por produto e por plataforma (modal ou rota /lucro/produto/[id]). Recalcular Metrica via job após cada venda/custo novo. Exportação CSV das vendas e do ranking.

Regras de segurança (hard rules)

  • !
    Gate de publicação: só entra na fila Criativo com podePostar === true. Validar no backend, não só na UI.
  • !
    Sem cópia: Tendencia.linkReferencia é só para análise — nunca baixar, repostar ou remover marca d'água.
  • !
    Aprovação obrigatória: publicação automática, fornecedor novo, 1ª campanha e risco jurídico sempre passam pelo painel "Aprovar Agora".
  • !
    Compliance de legenda: bloquear promessas absolutas ("garantido", "prometo") — vira alerta vermelho.

Motor de Decisão — lógica

// após coletar métricas de um conteúdo postado
if (performou === 'bem')   → marcar campeão · criar 5 variações · repetir produto
if (performou === 'medio') → trocar legenda · novo CTA · mudar horário
if (performou === 'fraco') → pausar formato · arquivar aprendizado

Integração de IA

Onde a IA entra, como conectar e como não estourar custo. Regra de ouro: a chave da IA fica só no servidor (nunca no bundle do front).

Onde a IA é usada

FunçãoEntra emSaída
Análise de tendênciaRadargancho, dor, formato, motivo viral, risco de cópia, score
Transformar em conteúdo próprioTransformador IA5 ganchos, 5 roteiros, 5 legendas A/B, CTAs, produtos sugeridos
Gerar legendas + hashtagsAprovar Agora, Publicaçãolegenda + até 5 hashtags + aviso de afiliado
Análise de performanceMotor de Decisão, Lucrocampeão/médio/fraco + próxima ação
Score de Escala + recomendaçãoLucro e Escala0–100 + texto de recomendação
Análise jurídica de riscoCompliancepromessa exagerada, falta de aviso, risco autoral

Arquitetura recomendada (Next.js)

// .env  — chave só no servidor
OPENAI_API_KEY=sk-•••        // ou ANTHROPIC_API_KEY / a IA que você usa
IA_MODELO=gpt-4o-mini        // barato para gerar em volume
IA_LIMITE_DIA=2000          // teto de gerações/dia por conta

// app/api/ia/gerar/route.ts  (Server Route — nunca no client)
export async function POST(req) {
  const { tipo, contexto, contaId } = await req.json()
  await checarCota(contaId)            // guardrail de custo
  const prompt = montarPrompt(tipo, contexto) // roteiro|legenda|analise…
  const r = await ia.chat({ model: process.env.IA_MODELO, messages: prompt })
  await registrarUso(contaId, r.usage) // para cobrança por créditos
  return Response.json(r.saida)
}
No protótipo, a IA é simulada (dados mock). Em produção, cada botão "Gerar" chama /api/ia/gerar. Os créditos por módulo (Conteúdo IA, Imagens, Lucro) usam o registrarUso() para descontar e exibir o medidor que já existe na Loja de Módulos.

Guardrails (obrigatórios)

  • !
    Chave no servidor. Nunca exponha a API key no front nem em NEXT_PUBLIC_*.
  • !
    Cota por conta/dia. Bloqueie acima do limite e ofereça compra de créditos extras.
  • !
    Cache. Reaproveite análises de tendência iguais para não pagar duas vezes.
  • !
    Fallback. Se a IA falhar, mostre rascunho editável — nunca trave o fluxo.
  • !
    Revisão humana. Saída de IA sempre passa pela usuária antes de publicar.

Funcionamento offline (PWA)

A plataforma deve abrir e ser usável sem internet — consultar conteúdos, calendário, produtos e rascunhar; sincronizando quando a conexão voltar.

O que funciona offline

Offline (lê e edita)Só online (precisa de rede)
Abrir o app e navegar (telas em cache)Gerar com IA (chama o servidor)
Ver calendário, conteúdos, produtos, metasPublicar nas redes / APIs
Escrever roteiros e legendas (rascunho)Sincronizar vendas e métricas
Marcar aprovação (entra na fila de sync)Conectar contas (OAuth)

Como implementar

// 1. PWA: manifest + service worker (next-pwa)
npm i next-pwa
// next.config.js → registra SW, faz cache do app shell e telas

// 2. Dados locais: IndexedDB (Dexie) como cache + fila offline
npm i dexie
db.rascunhos / db.filaSync / db.cacheTelas

// 3. Sincronização quando a rede volta
window.addEventListener('online', sincronizarFila)
// envia rascunhos, aprovações e edições pendentes ao servidor
Estratégia de cache: app shell + telas com stale-while-revalidate; dados em IndexedDB com fila de escrita offline. Um selo offline no topo avisa a usuária quando está sem rede e o que ficará pendente até sincronizar.
